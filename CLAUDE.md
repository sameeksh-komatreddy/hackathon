# BackTrack

The project is being rebuilt as a browser-only web app. For roadmap or "next session" work, read `docs/ROADMAP.md` first and follow its session steps. Read the other files under `docs/` only when the current session points to them.

- Don't read `legacy/` or `frontend_pm.html` in full; grep them.
- Commit messages: short and plain, 3–8 words, no prefixes.
- At the start of a roadmap session, outline its objectives in a few plain sentences.
- With that outline, briefly give the complexity (low/medium/high) and a recommended model and effort level for the current session and for the next one. Sessions marked ⚙ suit a lighter model.
- End each reply that changes something with a short plain-language footnote of what changed.
- Ask the user before making any key design or preference decision.
- Keep `docs/ROADMAP.md` current: tick items when done and update it when plans change.
